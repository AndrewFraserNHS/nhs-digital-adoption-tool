# Understanding handover

Welcome to the Adoption Engine. Originally developed in HTML by James and Jooli and taken over in 2026 by Andrew and Jooli to be brought to the current technical expectations.

The tool may look complicated at first but is simple at it's core. It is a list of about 700 actions that help a projects go from completely new, to fully adopted.

There are various stages, phases, components and lens but in simple terms they are all just ways of grouping or improving the actions provided to users.

We have various other apps within the tool, all of which are to benefit the user's understanding and creation of actions, or to share the outcomes of the actions. e.g. Highlight Builder

## Baseline and CST
The app, without any imports, comes with a default set of actions, links and an assessment.
This can be "customised" by updating project profile to house different links for a more specific project page, or update the assessment to have project specific questions.
You can export this new CST from the Project Profile page, and others can import and start from your new baseline.
This is different to an export on other pages which is a "Progress" export and is to share timestamped versions of the progress of outcomes and actions
The only complexity with progress exports is due to "proof" or evidence and this is converted to Base-64 and bundled, if there is a project with large or complex evidence, this could cause issues in future.

## Future

### Centralised system with Dashboard
With the application currently not having any backend, all changes are local and hard to assess. The biggest change of scope, that would provide the biggest impact would be to move from JSON files, to a full database/backend with SSO that would allow for senior team-members to have overview of all ongoing projects, get weekly reports and view dashboards of all the great work being done, and more importantly assure them that funding is being utilised correctly.

### CMS backed system/Futures replacement
All documents regarding change management are in a sharepoint-like system called Futures, which is a website where lots of information is entered, with attachments at the bottom of each page. It is a wealth of information but is access-based, and rather daunting to look at. TheAdoption Engine has pulled a lot of resources from Futures and the next logical step would be to move from code-based-copy, to having the tool backed by a CMS, such as Contentful, Umbraco, Optimizely or OrchardCMS, which would move all the resources out of Futures, and any pagecontent from the tool and allow non-technical staff to continue to add content, which then can be pulled into the Adoption Engine for easier access.
### Exam System
Jooli has mentioned that instead of a standard “Change Management Practitioner” exam that there is work being done on a NHS-specific version of this kind of exam, to provide more relevant examples and that having a tool like we already have developed, to sit alongside thistraining and exam, providing examples, and upskilling in the tool alongside general knowledge transfer feels like a no-brainer.

### Increased Tooling
There are various tools that are floating around Futures called CADAS tools, they are typically Javascript or HTML pages that allow staff to perform some useful action e.g. Decision Matrix. With them being scattered about and not integrated, they are losing significant impactand that were we to attain a list of all the CADAS tools, or even tools from the playbook that are beneficial for Change Managers, they can be integrated not only into the system, but with “Resolve” functionality that could pull out the decisions or learnings from the tool,into the Actions or Objectives the Project has.
The same applies to numerous spreadsheets the team are using, and could have better usability and accessibility within the tool

### NHS Project Kit
A far larger proposal, but if the Database and CMS work both were approved, you would then have a centralised tool, with de-coupled copy, that contains an abundance of useful tooling for change management. But is also an incredible resource for project work as a whole. 

The pitch would be that any new streams of work, would be brought on to the Adoption Engine, would get that treatment of making sure that the work is being adopted in the correct way, with senior stakeholders able to see this. But that once you do have that, 
-	You could link out to JIRA and track the status of tickets and sprints if it’s a development team. 
-	You could link it out to accounts/financial teams and give progress/£ breakdowns of the current quarter. 
-	You can remove the risk of duplication of effort and validate someone else in the country isn’t already progressing with a very similar idea
-	More and more tools can be added to the system to give all teams across NHSE a way to handle any situation, and by default following NHSE guidance as it would all be centralised.
